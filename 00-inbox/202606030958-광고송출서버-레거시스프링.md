# 광고 송출 서버 레거시 Spring 5 토이 프로젝트 시작 가이드

---

## 📝 원문

회사에서 Spring 5, Java 11, Maven, Tomcat 9, web.xml 방식의 레거시 서블렛 기반 광고 지면 송출 서버를 개발해야 한다. Spring Boot 경험만 있고 Servlet/레거시 Spring 경험이 부족하다. 고객 사이트의 지면에 광고를 보여주는 송출 1파트이며, 기술 스택은 Java 11, Jenkins, Tomcat 9, MySQL, Kafka, MongoDB, Redis이다. 집에서 토이 프로젝트로 하나씩 연습하고 싶다.

---

## 🔍 내 노트 기반 답변

### 기존 지식과의 연결점

내가 이미 정리한 [[topics/java/concepts]], [[topics/kafka/concepts]], [[topics/redis/concepts]], [[topics/mongodb/concepts]] 의 지식이 모두 이 프로젝트에 직접 적용된다. Spring Boot가 자동으로 해주던 것들을 직접 XML로 선언하는 구조이므로, 기존 Spring Boot 지식을 "언래핑"하는 과정이다.

광고 송출 서버는 [[topics/system-design/concepts]] 에서 다루는 고가용성/저지연 설계가 핵심이다. 실시간 트래픽 처리 경험(WebSocket 채팅, 라이브 스트리밍)이 직접적으로 활용된다.

## 1. 프로젝트 개요 및 아키텍처

### 광고 송출 서버(Ad Serving Server)란?

```
고객 사이트 (Publisher)
    │
    │ 1. 광고 지면 요청 (HTTP GET /ad?zoneId=xxx&userId=yyy)
    ▼
광고 송출 서버 (Ad Server — 이 프로젝트)
    │
    ├─► Redis    : 캠페인/크리에이티브 캐싱, 빈도수(Frequency Cap) 관리
    ├─► MongoDB  : 광고 소재(크리에이티브), 타겟팅 메타데이터
    ├─► MySQL    : 캠페인, 광고주, 지면 정보 (마스터 데이터)
    └─► Kafka    : 노출(Impression) 이벤트 발행 → 집계/정산 파이프라인
    │
    │ 2. 광고 응답 (JSON or HTML snippet)
    ▼
고객 사이트 렌더링
```

### 핵심 API 흐름

| 단계 | 내용 |
|------|------|
| 1. 지면 요청 | `GET /ad/serve?zoneId=&userId=&ua=` |
| 2. 타겟팅 | userId 기반 타겟 조회 (Redis 캐시 우선) |
| 3. 광고 선택 | 우선순위/입찰가 기반 광고 선택 (MySQL 캠페인 조회) |
| 4. 소재 조회 | MongoDB에서 크리에이티브(이미지URL, 카피) 조회 |
| 5. 노출 기록 | Kafka로 Impression 이벤트 발행 (비동기) |
| 6. 응답 반환 | JSON 응답 (광고 소재 URL, 클릭 트래킹 URL 포함) |

### 8-2. Kafka Producer (비동기 노출 이벤트)

```java
// com/adserver/kafka/ImpressionProducer.java
@Component
public class ImpressionProducer {

    private final KafkaProducer<String, String> producer;
    private final String topic;

    @Autowired
    public ImpressionProducer(
            @Value("${kafka.bootstrap.servers}") String servers,
            @Value("${kafka.topic.impression}")  String topic) {

        this.topic = topic;
        Properties props = new Properties();
        props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, servers);
        props.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,   StringSerializer.class);
        props.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        props.put(ProducerConfig.ACKS_CONFIG, "1");
        this.producer = new KafkaProducer<>(props);
    }

    public void sendImpression(String adId, String userId, String zoneId) {
        String payload = String.format(
            "{\"adId\":\"%s\",\"userId\":\"%s\",\"zoneId\":\"%s\",\"ts\":%d}",
            adId, userId, zoneId, System.currentTimeMillis()
        );
        producer.send(new ProducerRecord<>(topic, adId, payload));
        // 광고 송출 응답 속도에 영향 안 주려고 fire-and-forget
    }
}
```

### 8-3. 광고 선택 서비스

```java
// com/adserver/service/AdServingService.java
@Service
public class AdServingService {

    @Autowired private JdbcTemplate jdbcTemplate;
    @Autowired private RedisTemplate<String, Object> redisTemplate;
    @Autowired private MongoTemplate mongoTemplate;
    @Autowired private ImpressionProducer impressionProducer;

    public AdResponse serve(String zoneId, String userId) {
        // 1. Redis에서 빈도수 체크 (Frequency Cap: 같은 광고 하루 5회 이하)
        String freqKey = "freq:" + userId + ":" + zoneId;
        Long count = redisTemplate.opsForValue().increment(freqKey);
        if (count == 1) {
            redisTemplate.expire(freqKey, 1, TimeUnit.DAYS);
        }

        // 2. MySQL에서 활성 캠페인 조회 (캐싱 가능 영역)
        String cacheKey = "campaign:zone:" + zoneId;
        String campaignId = (String) redisTemplate.opsForValue().get(cacheKey);
        if (campaignId == null) {
            campaignId = jdbcTemplate.queryForObject(
                "SELECT id FROM campaigns WHERE zone_id = ? AND status = 'ACTIVE' " +
                "ORDER BY bid_price DESC LIMIT 1",
                String.class, zoneId
            );
            redisTemplate.opsForValue().set(cacheKey, campaignId, 5, TimeUnit.MINUTES);
        }

        // 3. MongoDB에서 크리에이티브 조회
        Query query = new Query(Criteria.where("campaignId").is(campaignId));
        Document creative = mongoTemplate.findOne(query, Document.class, "creatives");

        // 4. Kafka로 노출 이벤트 발행 (비동기)
        impressionProducer.sendImpression(campaignId, userId, zoneId);

        // 5. 응답 반환
        return AdResponse.builder()
            .adId(campaignId)
            .creativeUrl((String) creative.get("imageUrl"))
            .clickUrl("https://ad.example.com/click?adId=" + campaignId + "&userId=" + userId)
            .title((String) creative.get("title"))
            .build();
    }
}
```

### 8-4. Controller

```java
// com/adserver/controller/AdController.java
@RestController
@RequestMapping("/ad")
public class AdController {

    @Autowired private AdServingService adServingService;

    @GetMapping("/serve")
    public ResponseEntity<AdResponse> serve(
            @RequestParam String zoneId,
            @RequestParam(required = false, defaultValue = "anonymous") String userId) {

        AdResponse response = adServingService.serve(zoneId, userId);
        return ResponseEntity.ok()
            .header("Cache-Control", "no-store")  // 광고는 캐싱 금지
            .body(response);
    }

    @GetMapping("/health")
    public ResponseEntity<String> health() {
        return ResponseEntity.ok("OK");
    }
}
```

## 10. Jenkins 배포 파이프라인 (Jenkinsfile 기초)

```groovy
// Jenkinsfile
pipeline {
    agent any

    tools {
        maven 'Maven3'
        jdk   'JDK11'
    }

    stages {
        stage('Checkout') {
            steps { checkout scm }
        }
        stage('Build') {
            steps {
                sh 'mvn clean package -DskipTests'
                // 결과: target/ad-server-1.0-SNAPSHOT.war
            }
        }
        stage('Test') {
            steps { sh 'mvn test' }
        }
        stage('Deploy to Tomcat') {
            steps {
                // Tomcat Manager API로 WAR 배포
                sh '''
                    curl -u admin:password \
                    "http://tomcat-server:8080/manager/text/undeploy?path=/ad-server"
                    
                    curl -u admin:password \
                    -T target/ad-server-1.0-SNAPSHOT.war \
                    "http://tomcat-server:8080/manager/text/deploy?path=/ad-server&update=true"
                '''
            }
        }
    }
}
```

## 11. Spring Boot와의 핵심 차이 — 체감 비교표

| 항목 | Spring Boot | Spring 5 레거시 |
|------|-------------|-----------------|
| 진입점 | `@SpringBootApplication` | `web.xml` |
| Bean 등록 | 자동 (`@EnableAutoConfiguration`) | XML `<bean>` 선언 |
| DataSource | `application.yml` 한 줄 | `applicationContext.xml` + `database.properties` |
| 서버 | 내장 Tomcat (JAR) | 외부 Tomcat에 WAR 배포 |
| Context | 하나 | Root + Web 두 개 (Parent-Child 구조) |
| 트랜잭션 | `@Transactional` + 자동 설정 | `<tx:annotation-driven>` 명시 필수 |
| 빌드 | `mvn spring-boot:run` | `mvn package` → WAR → Tomcat에 배포 |

**Parent-Child Context 구조** (레거시 Spring 핵심 개념):
```
Root ApplicationContext (applicationContext.xml)
  └─ Service, Repository, DataSource, Kafka, Redis, MongoDB
      ↑ 부모 (자식이 부모 Bean 참조 가능)
Web ApplicationContext (dispatcher-servlet.xml)
  └─ Controller, ViewResolver
      (부모 Bean은 참조 가능, 반대는 불가)
```
