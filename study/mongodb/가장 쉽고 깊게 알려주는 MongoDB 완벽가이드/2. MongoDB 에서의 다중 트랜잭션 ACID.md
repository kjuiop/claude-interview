### Json vs Binary Json

![[Pasted image 20260614065526.png]]

- BSON
	- Json 의 한계를 보완, 텍스트 기반의 JSON 보다 성능이 더 좋음
	- BSON 은 키와 필드명 모두를 저장하기 때문에 필드명이 길어지거나 중첩되는 문서가 많아지면 데이터 량이 많음
	- BSON 은 데이터 타입을 같이 저장하기 때문에 필요한 데이터만 가져옴

- MongoDB Clinet
	- mongodb 드라이버가 Javascript 의 object 를 내부적으로 BSON 으로 변환 및 저장함

- objectId, data Type
	- mongodb 는 문서를 생성할 때 기본적으로 _id 를 생성함 (default)
	- bson 의 object_id 를 의미
	- 생성되는 시점과 host process 의 카운트 정보로 문서마다 unique 한 값
	- data type 도 저장 가능
	- object_id 는 timestamp 도 포함해서 저장하기 때문에 정렬도 가능

- 이진데이터 
	- bson 이 바이너리 타입이기 때문에 이미지나 파일 등 비정형 데이터도 원활하게 다룰 수 있음
	- greenfs 도 대용량 파일도 청크 형태로 분할하여 관리함


### mongoDB 에서의 다중 트랜잭션 (ACID)

![[Pasted image 20260614070531.png]]

- mongodb 는 4.0 이전에서는 다중 문서에서의 트랜잭션을 지원하지 않음


- 트랜잭션이 적용되기 위해 필요한 부분
	- 레플리카셋
		- 데이터 복제 없이는 데이터 무결성을 보장할 수 없기 때문
		- 레플리카에서 Secondary DB 가 데이터 복제를 위해 사용하는 로그  oplog (로그성 데이터로 복제하게됨)
		- 단일노드는 데이터 복제를 하지 않으므로 oplog 가 없음
	- 샤딩 클러스터
	- wired tiger 스토리지 엔진 
		- mongodb 4.0 이상에서는 이 엔진을 사용하게 됨


- 트랜잭션 동작 방식
	- 격리수준 : readed committed, 다른 트랜잭션이 커밋한 것을 읽을 수 있는 격리 수준
		- 격리 수준은 변경 가능
	- 스냅샷 isolation : 트랜잭션 진행 중에는 데이터가 외부에서 변경되지 않는 것을 의미
		- 트랜잭션을 시작하는 단계 : 데이터베이스가 스냅샷을 찍게 됨
		- 트랜잭션이 동시에 시작될 때 : 다른 트랜잭션이 데이터를 변경해도 데이터는 처음 시작할 때 생성한 스냅샷을 기준으로 데이터를 사용함
		- 장단점
			- 데이터의 높은 일관성
			- write concern
				- x, y 트랜잭션이 동시에 발생하고 같은 문서를 수정하는 상황
				- x, y 는 문서를 복제본을 뜨고 x 는 1로 수정, y는 b로 수정
				- x 는 문서를 flush 로 반영함, y는 반영하려고 했는데 최초 스냅샷이 달라서 데이터 쓰기에 실패함
				- 이러한 충돌 상황에서 더 큰 손해를 볼 수 있음
				- 일반적으로는 재시도로직으로 함 -> 현실적으로는 다중 트랜잭션을 사용하지 않음
