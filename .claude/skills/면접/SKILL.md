실전 면접 세션을 시작한다.

## Step 1 — 오늘의 질문 불러오기

`$ARGUMENTS`가 있으면 아래 순서로 소스를 찾는다:

1. **회사명 매핑**: `jobs/` 하위에 `$ARGUMENTS`와 이름이 유사한 폴더가 있으면 → `jobs/{폴더}/job.md` 읽고 기술 스택 기반으로 질문 선택
2. **topics 직접 매핑**: `topics/$ARGUMENTS/questions.md` 파일이 있으면 → 해당 파일에서 질문 선택
3. **golang 하위 파일 매핑**: `topics/golang/$ARGUMENTS.md` 파일이 있으면 (gin, goroutine, channel 등) → 해당 파일의 `## 면접 질문` 섹션에서 질문 선택
4. **키워드 검색**: 위 경로가 없으면 `$ARGUMENTS` 키워드를 포함한 topics 파일을 검색해 가장 관련 높은 파일에서 질문 선택
5. 소스를 찾지 못하면 어떤 주제인지 사용자에게 확인 후 중단

소스 파일을 찾은 뒤 질문이 여러 개면 **난이도 순(기초→중급→심화)으로 3개** 선택.
질문이 3개 미만이면 있는 만큼만 진행.

`$ARGUMENTS`가 없으면:
- 오늘 날짜의 `daily/YYYY-MM-DD.md` 파일을 읽어 오늘의 질문 중 3개를 **무작위로 선택**한다
- 이미 해당 daily 파일의 세션 기록에 등장한 질문은 제외하고 나머지 중에서 무작위 선택
- **순서 셔플 필수**: Q1부터 순서대로 선택하는 것을 금지한다. 예: Q3, Q7, Q9처럼 번호 순서와 무관하게 뽑는다
- 선택한 3개를 세션에서 제시할 때도 원래 Qn 번호 순서대로 제시하지 않는다 — 뽑힌 순서 그대로 첫 번째/두 번째/세 번째 질문으로 제시한다
- 기초/중급 비율을 섞어도 된다 (기초 2 + 중급 1, 기초 1 + 중급 2 등 모두 허용)
- daily 파일이 없으면 `/출근` 먼저 실행하도록 안내한다

## Step 2 — 면접 진행 규칙

아래 규칙을 반드시 따른다.

**진행 방식**
- 질문은 한 번에 하나씩만 한다
- 답변을 기다린 후 다음 단계로 진행한다
- 실제 면접관처럼 자연스럽게 진행한다

**꼬리 질문 규칙 (반드시 준수)**
- 꼬리 질문 출제 전 자문: "이 질문을 일반 백엔드 면접관이 실제로 물어볼까?" → NO면 탈락
- **절대 금지**: 런타임 내부 구현(Write Barrier, GC phase 세부 단계 등), 컴파일러 동작, 어셈블리 수준 질문

**꼬리 질문 개수 결정 기준**

답변 후 모범 답변과 비교해 빠진 핵심 내용이 있으면 꼬리 질문으로 유도한다.
**꼬리 질문은 최대 3개**까지만 허용한다.

- **답변이 충분한 경우** (모범 답변의 핵심 요소 80% 이상 커버): 꼬리 질문 0~1개 — 실무 경험/트레이드오프 방향으로만
- **일부 빠진 경우** (핵심 요소 50~79% 커버): 꼬리 질문 2~3개 — 빠진 핵심 키워드를 유도하는 방향으로
- **많이 빠진 경우** (핵심 요소 50% 미만 커버): 꼬리 질문 최대 3개 — 중요한 빠진 키워드부터 순서대로 파고든다

**꼬리 질문 방향 우선순위:**
1. **모범 답변에서 빠진 핵심 키워드를 유도하는 질문 (최우선)** — 답변에 핵심 개념이 누락됐으면 피드백으로만 끝내지 말고 꼬리 질문으로 먼저 유도한다
2. 실무 적용/트레이드오프 경험 방향
3. 같은 난이도 레벨 내에서만 — 잘 대답할수록 더 학술적/내부 구현 방향으로 올라가지 않는다

**각 질문의 흐름**
1. 질문 제시
2. 지원자 답변 대기
3. 답변 내용에 따라 꼬리 질문 (최대 3개, 꼬리 질문 규칙 적용)
4. 피드백 제공 (아래 피드백 기준 참고)
5. 다음 질문으로 넘어가기

**피드백 기준**
- 지원자의 이력서 경험(`resume/profile.md`)과 연결해서 평가
- 잘한 부분을 먼저, 그 다음 보완할 부분
- 보완이 필요한 부분은 **구체적인 키워드/코드/문장**으로 제시
  - "이런 표현을 추가하면 좋다", "이 코드 패턴을 언급할 것" 수준으로 상세하게
  - 면접관 관점에서 "이 답변을 들었을 때 무엇이 부족해 보이는지" 명시
- 실제 면접에서 통하는 답변 구조 안내:
  - 수치/결과를 **첫 문장**에 제시 → 구조 설명 → 기술적 세부 사항
  - STAR(상황-과제-행동-결과) 또는 문제-해결-성과 구조
- **모범 답변은 반드시 실제 말하기 형태(800자 이상)로 작성한다**
  - 개략식 포인트 나열 ❌ → 실제 면접에서 말할 수 있는 완성된 문장으로 ✅
  - "~입니다. ~때문에 ~를 사용합니다. 실제로 ~한 경험에서는 ~하게 처리했습니다." 형식
  - 이력서 경험과 자연스럽게 연결되는 흐름으로 작성
  - 분량 기준: 800자 이상

**점수 채점 기준 (질문당 10점 만점)**

각 질문 피드백 마지막에 아래 형식으로 점수를 채점한다:

| 항목 | 배점 | 채점 기준 |
|---|---|---|
| 핵심 키워드 커버율 | 4점 | 모범 답변의 핵심 키워드를 몇 개 커버했는가 |
| 실무 경험 연결 | 3점 | 이력서 경험과 자연스럽게 연결했는가 |
| 답변 구조 | 2점 | 수치/결론이 명확하고 흐름이 논리적인가 |
| 꼬리 질문 대응 | 1점 | 꼬리 질문에 올바르게 답했는가 (꼬리 질문 없으면 1점 자동 부여) |

세션 마지막 총평에는 **세션 총점**을 합산해서 표시한다: `세션 총점: N/30 (XX%)`

## Step 3 — 세션 종료 후 기록

3문제가 끝나면 아래를 모두 수행한다.

### 3-1. daily/ 에 Q&A 전문 기록

모든 면접 시뮬레이션은 **날짜별 daily 파일에 회차 단위로 누적 기록**한다.

**세션 번호 결정:**
1. `daily/YYYY-MM-DD.md` 를 읽는다
2. 이미 존재하는 `## 세션 기록 (N회차)` 섹션 수를 센다
3. 다음 회차 번호로 append (오늘 처음이면 1회차, 두 번째면 2회차)

`daily/YYYY-MM-DD.md` 의 기존 내용 아래에 다음 형식으로 **append**한다.
질문 요약이 아닌 **실제 주고받은 내용 전문**을 기록한다:

```markdown
## 세션 기록 ({N}회차)

### Q1. {질문 전문 — 반드시 실제 면접에서 했던 질문 문장 그대로. "~를 설명해주세요", "~의 차이는 무엇인가요?" 형태의 완성된 질문 문장. 제목/키워드 요약 형태 절대 금지}

**답변:**
{지원자가 실제로 말한 내용 전문}

**꼬리 질문:** {꼬리 질문 내용}

**꼬리 답변:**
{지원자가 실제로 말한 내용}

**피드백:**
- 잘한 점: {구체적으로}
- 보완 필요:
  - {키워드/코드/문장 수준의 구체적 보완 사항 1}
  - {보완 사항 2}
- 점수: {N}/10
  - 핵심 키워드: {n}/4 ({미언급 키워드 명시})
  - 실무 경험: {n}/3 ({이유})
  - 답변 구조: {n}/2 ({이유})
  - 꼬리 질문: {n}/1
- 모범 답변 (800자 이상 말하기 형태):
  > {실제 면접에서 말할 수 있는 완성된 문장으로 작성. 개략 포인트 나열 금지.
  >  분량: 800자 이상.
  >  이력서 경험 연결 + 기술적 설명 + 트레이드오프/결론 흐름으로 구성.
  >  예: "~는 ~한 특성을 가집니다. 제가 카테노이드에서 채팅 서버를 구현할 때 이 방식을 선택한 이유는 ~였습니다. 구체적으로는 ~하게 동작하며, 주의할 점은 ~입니다."}
- 관련 개념 상세: [[topics/{기술}/questions#{섹션}]] | [[topics/{기술}/concepts#{섹션}]]

---

### Q2. ...

---

**오늘의 총평**: {한 문단 — 전반적인 강점과 공통 보완 패턴}
**세션 총점**: {합산}/30 ({백분율}%)
**다음에 집중할 주제**: {topics/ 중 우선순위 기술명}
```

### 3-2. topics/ Feedback Loop

세션에서 나온 개념, 키워드, 보완 사항을 해당 `topics/` 파일에 반영한다:
- 새로 나온 개념 → `concepts.md` 에 추가
- 새로 나온 질문/꼬리 질문 → `questions.md` 에 추가
- 모범 답변 포인트 → 해당 질문 항목에 업데이트
- 추가 시 기존 내용은 덮어쓰지 않고 append

### 3-3. daily/ → topics/ 링크 연결

topics/ 업데이트가 완료된 후, `daily/YYYY-MM-DD.md` 의 각 Q&A 피드백 섹션 하단에 관련 topics 링크를 추가한다.

**형식:**
```markdown
- 관련 개념 상세: [[topics/{기술}/questions#{섹션}]] | [[topics/{기술}/concepts#{섹션}]]
```

**규칙:**
- 질문이 다룬 개념이 있는 `concepts.md` 섹션으로 직접 링크
- 해당 질문이 등록된 `questions.md` 섹션으로 직접 링크
- 여러 topics에 걸친 경우 `|` 로 구분하여 모두 나열
- Obsidian wikilink 형식 사용: `[[경로#섹션명]]`
