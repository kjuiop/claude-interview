---

오늘 면접에서 부족했던 키워드를 심층 정리한다. 반드시 아래 순서대로 실행한다.

## 커맨드 인수 처리

`/피드백 {추가 텍스트}` 형식으로 호출된 경우:
- `{추가 텍스트}`를 **추가 보완 요청**으로 해석한다
- 예: `/피드백 kafka idempotent producer 더 자세히` → Kafka Idempotent Producer 항목을 우선 심화 정리
- 예: `/피드백 postgresql mvcc vacuum` → PostgreSQL MVCC + VACUUM 항목 우선 심화
- 추가 텍스트가 없으면 오늘 세션의 보완 필요 항목 전체를 대상으로 진행

---

## Step 1 — 오늘 세션 분석

오늘 날짜의 `daily/YYYY-MM-DD.md` 파일을 읽는다.

다음을 추출한다:
1. **보완 필요** 항목에서 언급된 모든 키워드/기술 용어
2. **꼬리 답변이 "모름"인 항목** — 가장 우선순위 높음
3. 추가 텍스트가 있으면 해당 키워드를 목록 최상단에 추가

추출 결과를 내부적으로 **우선순위 목록**으로 정리한다:
- 1순위: "잘 모르겠습니다" 답변이 나온 개념
- 2순위: 피드백에서 "미언급" 또는 "오개념"으로 지적된 개념
- 3순위: "추가로 알면 좋다"고 언급된 개념

---

## Step 2 — 웹 검색으로 각 키워드 심층 조사

우선순위 목록에서 **상위 3~5개 키워드**를 선택한다.
각 키워드마다 다음을 병렬로 검색한다:

- `{키워드} 동작 원리 상세`
- `{키워드} golang 구현 예시` (Go 관련 개념인 경우)
- `{키워드} 면접 답변 예시`
- `{키워드} best practices 2025`

검색 결과에서 다음을 수집한다:
- 개념의 정확한 정의
- 내부 동작 원리 (가능하면 코드/다이어그램 수준)
- 실무에서 어떤 상황에 쓰이는지
- 면접에서 자주 묻는 꼬리 질문 패턴
- 흔한 오개념 또는 함정

---

## Step 3 — topics/ 파일에 정리

각 키워드에 해당하는 `topics/{기술}/concepts.md` 와 `topics/{기술}/questions.md` 를 업데이트한다.

**작성 원칙:**
- 기존 내용은 덮어쓰지 않고 **append**
- 이미 있는 내용은 보강만 (중복 금지)
- 코드 예시가 있으면 반드시 포함
- 면접 답변 구조(모범 답변 흐름)를 questions.md에 명시

**concepts.md 작성 형식:**
```markdown
## {개념명}

### 정의
{한 줄 정의}

### 동작 원리
{내부 동작 상세 — 코드/다이어그램 포함}

### 실무 사용 시나리오
{언제 쓰는지, 왜 쓰는지}

### 주의할 점 / 흔한 오개념
{함정, 잘못 알기 쉬운 부분}
```

**questions.md 작성 형식:**
```markdown
### Q. {질문}

**핵심 답변 포인트:**
1. {포인트 1}
2. {포인트 2}
...

**코드 예시:** (있는 경우)
```{언어}
{코드}
```

**꼬리 질문 대비:**
- "{예상 꼬리 질문}" → {핵심 답변}

**모범 답변 구조:**
{답변 흐름을 한 줄로}
```

---

## Step 4 — 정리 결과 대화창에 요약 출력

모든 파일 업데이트가 끝난 후 대화창에 아래 형식으로 출력한다:

```
## 피드백 정리 완료

### 오늘 보완한 키워드
- {키워드 1}: {한 줄 요약} → [[topics/{기술}/concepts#{섹션}]]
- {키워드 2}: {한 줄 요약} → [[topics/{기술}/concepts#{섹션}]]
...

### 각 키워드 핵심 요약
{키워드별로 "이것만 기억하라"는 핵심 포인트 2~3줄씩}

### 다음에 꼭 말해야 할 문장
{실제 면접에서 쓸 수 있는 한 문장짜리 핵심 표현 목록}
```

---

## 주의사항

- 웹 검색 결과가 충분하지 않으면 추가 검색 키워드를 변형해 재시도
- 개념 설명은 "면접에서 말할 수 있는 수준"으로 — 논문 수준 아님
- 코드 예시는 Go 또는 해당 기술의 표준 언어로 작성
- 검색 결과 간 내용이 충돌하면 공식 문서 또는 더 최신 자료 우선
